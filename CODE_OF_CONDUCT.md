# Code of Conduct

This is a short code of conduct, adapted from the
[Contributor Covenant](https://www.contributor-covenant.org), version 2.1.
It applies to issues, pull requests, discussions, commit messages, and any
other space where someone is taking part in this project.

## What is expected

- **Be decent.** Disagree with the idea, not the person. No insults, no
  harassment, no personal attacks, no following someone from thread to thread.
- **No contempt for the people this app is for.** This project exists because
  vendor software is often Windows-only, closed, or simply does not work on
  Linux. "Just use Windows", "buy a different keyboard", and similar are not
  acceptable answers here.
- **No gatekeeping.** Basic questions about GTK, Rust, udev, hidraw, or the
  keyboard are welcome. Point people at the README and `PROTOCOL.md` before
  telling them to read the whole codebase.
- **No vendor or distro wars.** Fedora, Debian, Arch, openSUSE, GNOME, KDE and
  everything else are welcome. Do not turn a support thread into a fight about
  which one is "correct".
- **No harassment of any kind**, including on the basis of age, body size,
  visible or invisible disability, ethnicity, sex characteristics, gender
  identity and expression, level of experience, education, socio-economic
  status, nationality, personal appearance, race, religion, or sexual identity
  and orientation.
- **Respect privacy.** Do not post someone else's personal information,
  screenshots, usage data, device serial numbers, or USB identifiers without
  their permission.

## What is not welcome

Sustained disruption, spam, advertising, cryptocurrency or "growth hacking"
pitches, and anything that pushes this project toward accounts, cloud sync,
analytics, telemetry, or advertising. Those are not up for debate; see the
README.

## Scope

This code applies in all project spaces, and when an individual is officially
representing the project in public.

## Enforcement

The maintainer decides what happens. Responses are proportionate to the
behaviour, and may range from a private word, to editing or deleting a comment,
to locking a thread, to a temporary or permanent ban from the repository.

There is no appeal process beyond talking to the maintainer once, calmly, by
email.

## Reporting

Report a problem to **emin.by@outlook.com**. Reports are read by the maintainer
and are kept confidential. Please include links, screenshots, and dates if you
have them.

If the report is about the maintainer, say so — it will still be read, and the
answer may honestly be that this is a one-person project with no independent
arbiter.
